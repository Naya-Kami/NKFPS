# NKFPS — オンラインFPSゲームへの開発プロジェクト

**最終目標は、フォトリアルなフル3DのオンラインFPSゲームを制作し、PC・iPad・スマートフォン・ゲームパッドで遊べるようにすることです。**

現在はその土台となる3DワールドをThree.jsで開発しています。提供された設計画像を基に、**BLACKSITE ECHO・SKYPORT NEXUS・TERMINAL BELOWの3枚を、それぞれ独立したマップとして再構成**しています。いまの3Dマップビューアーを完成形として終えるのではなく、ここからFPSの操作・戦闘・オンライン対戦へ発展させます。

**[ブラウザーで開く](https://blacksite-echo-world.syaseishizuju.chatgpt.site)** · [素材とライセンス](public/THIRD_PARTY.md)

iPadでは上のURLをSafariで開いてください。現在の機能はマップの閲覧と探索です。射撃・対戦・オンラインマルチプレイは未実装です。

## 起動とビルド

Node.js **22.12以上**を使用してください。Node.js 24で検証しています。

```bash
npm ci
npm run dev
```

ターミナルに表示されるURLをブラウザーで開きます。

```bash
npm run check   # JavaScript構文の検証
npm test        # マップ・描画設定・移動物理の検証
npm run build   # 配信用ファイルを dist/ に生成
```

本番配信では `dist/` をHTTPSでホスティングします。Three.js、フォント、PBR素材、HDR、参考画像は同じオリジンから読み込み、実行時に外部CDNへ依存しません。`node_modules/` と `dist/` はGitに含めません。

GitHub Pagesは `main` への更新を検証・ビルドし、生成した `dist/` を公開します。配信元を **Settings → Pages → Source → GitHub Actions** にすると、GitHubのブランチ配信を待たずに公開できます。

## 3つのマップ

| マップ | 空間の構成 | 主な高低差と接続 |
| --- | --- | --- |
| **BLACKSITE ECHO** | 海岸の研究施設。南の入口、中央の中庭・リアクターピット・封じ込めコア、左の研究棟/A、右のラボ/B、崖道と海上桟橋 | ピットは地下4.2m、中央キャットウォークは上階4.2m。左右の階段と、コア周囲の低いギャラリーで接続 |
| **SKYPORT NEXUS** | 空中空港。中央ガラスアトリウムとリング、左右のGate A/B・コンコース、北の保安検査と防衛側、南の出発ロビー | 保安検査2m・防衛側4.2m・外周サービス通路1.2m・ドック−2.5m。上階への階段、サービス連絡路、実際の出入口に合うドック階段で接続 |
| **TERMINAL BELOW** | 地下駅。南北の改札、2本の列車とホーム、中央通路、A/B、左右の保守トンネル | 中央橋3.4m、線路−1.2m、中央通路−0.8m。列車上の橋へは左右の階段、北の防衛側へは短い階段で接続 |

画像の外形、主要区画、A/Bサイト、中央のランドマークの位置関係を維持しています。`public/references/` の画像を「元画像と比較」から並べて確認できます。これらは**設計参考画像**で、ゲーム画面のスクリーンショットではありません。

原図は測量図ではないため、絶対寸法・壁高・隠れた構造は暫定です。座標は画像1pxを0.1mに変換し、画像上で階段や壁が重なっていた箇所には、歩行に必要な局所的な開口・踊り場・接続を補っています。

## マップと物理の見直し

見た目の床と当たり判定が食い違わないよう、床・橋・段差・階段の開口を共通の構造データから生成します。

- **落下と着地**：床のない場所に高さ0の床を仮定する処理を廃止。箱・橋・踊り場に着地し、落下がマップの下限に達すると最後の安全な足場へ戻ります。
- **頭上の衝突**：天井・橋の下面・出入口の梁で上昇を止めます。階段の上に床や天井が重なる区間には、実際のメッシュにも階段用の開口を設けます。
- **手すりと設備**：手すり、樽、タンク、ボラード、リアクターなどに静的な当たり判定があります。上階の小物は支持する床の高さに合わせます。
- **移動**：短いサブステップで薄い壁の通り抜けを防ぎます。低い段差を越え、壁沿いには滑ります。ジャンプは押した瞬間に1回発生し、押し続けても着地後に連続ジャンプしません。
- **構造の説明**：階段には側桁と手すり支柱、橋と出発案内デッキには支持柱を追加。出入口の枠・梁・区画表示、壁に沿う配線と照明で空間の用途と接続を示します。
- **細部の整合性**：回転したコンテナの補強材とラベルの向きを本体に合わせ、列車の車輪をレールの位置・高さに合わせています。船は船体と上部構造をまとめて揺らします。

移動物理はプレイヤーと静的な建築物の衝突を扱います。壁・手すり・箱・円柱・床板・階段を近似形状として扱い、4m区画の空間インデックスで照合対象を絞っています。箱を押す、建物が壊れる、飛行機が飛ぶ、といった剛体シミュレーションは実装していません。

## 操作

上部タブでマップを切り替えます。「俯瞰図」は北が上の平面表示、「3Dビュー」はドラッグで回転する立体表示です。「探索する」で開始地点へ、「各エリアへ移動」で区画を選べます。

| 操作 | PC | iPad / スマートフォン | 標準ゲームパッド |
| --- | --- | --- | --- |
| 移動 | WASD / 矢印キー | 左のスティック | 左スティック |
| 視点 | マウス / ドラッグ | 画面をドラッグ | 右スティック |
| ジャンプ | Space | ↑ボタン | A / Cross |
| 走る | Shift | — | 左スティック押し込み |
| ライト | F | ライトボタン | Y / Triangle |
| 全体マップ | M | ミニマップをタップ | View / Select |
| ミニマップ開閉 | N | 右上の − / ＋ | — |
| 一時停止 | Esc | 一時停止ボタン | Menu |

マウスが固定されないブラウザーではドラッグで視点を動かせます。俯瞰時の拡大・縮小は＋/−、ホイール、ピンチで操作できます。

## ミニマップと画質

探索中の右上に、現在位置・向き・A/Bサイト・高所を示すミニマップがあります。「周辺」は現在地を中心にした40m範囲、「全体」はマップ全体です。タップまたはMで拡大し、主要地点へ移動できます。

歯車メニューから画質を選べます。設定は端末ごとに保存されます。

| 設定 | 目的 |
| --- | --- |
| PERFORMANCE | 描画解像度と照明数を抑える軽量設定 |
| BALANCED | タッチ端末の初期設定。負荷と質感を両立 |
| HIGH | 2K素材、接地影、精細な反射、ライトの影を使用 |
| ULTRA | 描画・接地影・反射・照明の予算を増やした設定 |

iPad/スマートフォンではRetina画面の描画ピクセル数に上限を設けます。モバイルHIGHは床、ULTRAは床と壁の2K素材を読み込みます。PCのHIGH/ULTRAは床・壁・岩・鋼材を2Kにします。元の解像度を維持した素材で、低解像度画像の引き伸ばしではありません。

物理ベースの材質、屋内/屋外の環境反射、プレイヤー周辺に集中させた影、反射のぼけ、SMAAなどを使っています。実際の画質と速度は端末のGPUに依存します。

今回の改善は解像度ではなく、物体の形・材質・光の当たり方を対象にしています。木箱・樽・配電盤をPoly HavenのCC0モデルへ置き換え、固有のUVと1Kの色・法線・金属度/粗さマップを使用します。3モデルの転送量は合計約852KiBです。同じ物体はインスタンス描画でまとめ、木箱は縦横比を変形させず、実寸に合う小物を積んで配置します。当たり判定も各個体の寸法と高さに合わせます。読み込みに失敗した場合は簡易形状で探索を継続します。

地下駅の列車は、丸い屋根、窓の開口とガラス、座席、手すり、扉、台車、車輪、車軸を分けて構築します。線路の中心位置と列車の配置を保ち、軌間は1.435mへ補正。レールを断面のある部品にし、枕木・レール・車輪が接する高さをそろえ、橋の下面との間隔も検証しています。操作盤は傾斜した操作面と小さな表示器・ボタン、機材ケースは蓋の継ぎ目・留め具・持ち手、発電機はファンと通気ルーバーを持ちます。

壁・床の過剰で均一な光沢と凹凸を抑え、地下駅の照明は白色の灯具と照射光を対応させています。巨大なスポーンの説明板は床から除き、注釈はHUDに残します。床には小さな擦れたA/Bのステンシルを置きます。微細な面取りの分割をモバイルで抑え、実物モデルを使う状態でも、建築・小物のモバイル向けメッシュを各マップ25万三角形以内に収めています。これは海・雲・影・反射などの追加描画を含むフレーム全体の上限ではありません。

曲面の形を保つ法線合成と非一様スケール時の法線変換にも対応しています。空港は同じ大気モデルから背景と環境反射を生成し、昼夜で空・霧・照明をまとめて切り替えます。雲は3D密度をサンプリングする柔らかな雲海、海の泡は島の外形から求めた距離場に沿う表現です。

ガラスドームの横目地と支持金物、桜の細枝と多数の小さな花、建物の換気口・照明金物、床タイルの目地と粗さの差を追加しています。塗装された金属は素地の金属と反射特性を分けています。照明は固定数のライトをフェードさせて切り替え、移動中の床反射はカメラに追従して更新します。

PCのHIGH/ULTRAはガラスの透過表現を有効にし、モバイルでは軽い透明表現を維持します。雲のサンプル数も画質設定で変更します。未使用の素材は初期ロードせず、大気の反射マップは空港を初めて開くときに生成します。

海岸施設では、参考図から再構成した屋根・デッキ・床面の高さを使い、雨筋が屋内や床下に入り込まないようにしています。雨が当たる床の一部に水たまりが生じ、濡れた場所の色・粗さ・反射がそろいます。雨を停止すると濡れ方も徐々に弱まります。床と壁の境目の暗さは、壁との距離から作った小さな共有テクスチャで補っています。

目線の高さでは、海岸施設に排水溝、擦れた荷捌きの塗装、壁に固定した配管、橋脚を追加しました。地下駅にはホーム端の点字ブロックと吊り案内、照明の電源を通すケーブルトレーがあります。空港では、発着案内や搭乗口のサイン、ドックの誘導塗装、ドームの支持金物を作り込んでいます。

さらに実写に近づけるには、各マップで代表的な一人称視点を決め、実写写真と並べて寸法・光源・影の色・汚れ方を見比べます。優先する場所は海岸の中庭からコアへ入る通路、駅のホームから列車を見る位置、空港の出発ロビーです。近くで見る建築部品の実寸モデルと、室内で光が壁や床に反射して回る間接光をこの範囲で仕上げ、端末別の描画時間を測ってから残りの区画へ広げます。

    maps/
      data/                  3枚の参考画像から読み取った座標
      atlas.js               座標変換・床・階段開口・接続
      geometry.js            床と開口のメッシュ生成
      model.js               建築・設備・静的衝突形状
      propAssets.js          実物PBRモデルの読み込み・積み付け・インスタンス描画

      navigation.js          通行確認と安全な出現位置
      environment.js         環境の組み立てと更新
      ocean.js / clouds.js   海岸線に沿う波と柔らかな雲海
      vegetation.js          小さな花を集合させた桜

    ui/minimap.js            ミニマップ
    rendering/
      quality.js             端末別の描画予算
      lighting.js            空と反射の一貫した昼夜照明
      lightBudget.js         固定予算内での照明選択とフェード
      naturalFields.js       海岸距離場と雲の密度データ
      surfaceContext.js      屋根・床高・壁際の共有テクスチャ
      coastalRain.js         屋根やデッキの位置に従う雨筋
public/
  references/                提供された設計画像
  assets/pbr/                CC0素材・HDR・取得元とハッシュ
  assets/props/              CC0のGLBモデル・取得元とハッシュ

現在の3Dマップ実装は `src/3dmap/` に集約し、将来の戦闘や通信のコードと混ざらないようにしています。FPS機能の実装時は、ゲーム進行・戦闘・オンライン通信をそれぞれ分離し、マップデータや移動物理はこのモジュールから再利用する方針です。未実装の機能を持つ空のフォルダーは作っていません。

## 検証と残っている課題

**45件の自動テスト**で、3マップの特徴・座標・床の面積・当たり判定・主要地点間の到達性、ミニマップ、描画上限、素材のハッシュを検証しています。実物GLBを読み込んだ状態で、積み荷の支持と寸法、各個体の当たり判定、線路への車輪の接地、列車と橋の間隔も確認します。GLBの画像はCPUテストではデコードを代替しているため、画像の発色・GPU表示は別途確認が必要です。移動物理には、落下、箱への着地、天井への衝突、薄い壁、ジャンプの押しっぱなし、階段開口を含みます。描画系テストでは、昼夜の明るさ、凹形状の海岸距離、雲の密度データ、照明の固定数とフェード、壁越しの光源選別、海岸施設の雨を遮る屋根と床の高さを検証します。**27本の階段を実際のプレイヤーコントローラーで往復**し、空港の左右サービス通路から保安検査への連絡も検証します。

今回の環境ではブラウザー操作と管理プレビューの接続に問題があるため、GPU上の表示、iPad実機の速度、実コントローラーでの操作は未確認です。自動テストが画面全体の見栄えや実機操作を保証するわけではありません。

今後の課題は、実機での描画確認、建築/小物の精密モデル化と衝突形状の改善、音響の作り込み、戦闘・アニメーション、サーバー権威型のオンライン同期です。
